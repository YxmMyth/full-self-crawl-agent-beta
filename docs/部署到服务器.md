# 部署：容器化 + Helmsman 网页控制台

> 本文档讲**容器化部署**——通过 Helmsman 网页控制台发起任务，每个 run 跑在
> 一次性 Docker 容器里。这是当前推荐的运行方式（取代早期 tmux + 直跑 CLI）。
>
> 旧的"在服务器上直接 `python -m src.main`"的玩法仍然可用（见 README Quick
> Start），但容器化提供：多人并发、一人一个隔离浏览器、网页看实时进度 + VNC
> 操作登录弹窗、崩了自动清理。

---

## 一、架构（怎么跑起来的）

```
你的浏览器
   │  SSH 隧道 -L 8080:127.0.0.1:8080
   ▼
Helmsman 控制台 (python -m web，绑定 127.0.0.1，无鉴权 → 只能隧道进)
   │  发起任务 → RunSupervisor
   ▼
docker run --rm fsc-run:dev  ← 每个 run 一个一次性容器
   ├─ 容器内：Xvfb 虚拟屏 + x11vnc + noVNC + Camoufox
   ├─ python -m src.main {explore|harvest|auto} <domain> <req>
   ├─ noVNC :6080 → 发布到宿主某个 loopback 端口 → 控制台 /vnc 代理
   └─ run 结束 → --rm 自动销毁容器
        │
        ├─ World Model / run 元数据 → PostgreSQL（容器外，走网络）
        └─ 产出（samples/data/...）→ bind mount 到宿主 artifacts/
```

**关键边界**：
- **控制台只绑 `127.0.0.1`、无应用层鉴权**——因为它能交互操作已登录的浏览器，
  绝不能裸暴露公网。访问一律走 SSH 隧道。
- **密钥按名转发**（`-e LLM_API_KEY` 不带值）——从控制台进程的环境拉，不进
  容器的 argv / 日志。
- **数据库**：容器内的 `localhost` 是容器自己，所以 supervisor 自动把
  `DATABASE_URL` 里的 `localhost/127.0.0.1` 改写成 `host.docker.internal`
  （配 `--add-host host.docker.internal:host-gateway`，Linux 也能用）。
- **产出落盘**：宿主 `artifacts/` bind mount 进容器 `/app/artifacts`，
  `Config.run_dir()` 在容器内外解析一致。

## 二、一次性安装

前置：Docker、Python 3.10+、可达的 PostgreSQL 16（本地容器或云库都行）。

```bash
git clone <repo-url> full-self-crawl-agent
cd full-self-crawl-agent

# 1. 控制台自己的 Python 依赖（控制台跑在宿主，不在容器里）
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
#    注意：Debian/Ubuntu 若报缺 venv，先 apt install python3.x-venv

# 2. 构建 per-run 镜像（含 Camoufox + Xvfb/noVNC + 项目代码，~4GB）
docker build -f docker/run.Dockerfile -t fsc-run:dev .

# 3. PostgreSQL —— 用 Docker 起一个最省事（schema 由 src 启动时自动建）
docker run -d --name fsc-postgres --restart unless-stopped \
  -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=recon_agent \
  -p 127.0.0.1:5432:5432 -v "$PWD/pgdata:/var/lib/postgresql/data" \
  postgres:16

# 4. 配置
cp .env.example .env
# 填 LLM_API_KEY / LLM_BASE_URL / LLM_MODEL / DATABASE_URL，并加上：
#   HELMSMAN_CONTAINERIZED=1     ← 开容器化（不写=每个 run 跑子进程，无隔离）
#   HELMSMAN_PORT=8080           ← 控制台端口（默认 8000；被占就换）
```

## 三、启动控制台

```bash
# 前台跑（调试用）
.venv/bin/python -m web

# 生产：systemd 托管（开机自启 + 崩溃重启）
cp scripts/helmsman.service /etc/systemd/system/helmsman.service
#   编辑 unit 里的 WorkingDirectory / ExecStart 路径 + HELMSMAN_PORT +
#   Environment=HELMSMAN_CONTAINERIZED=1
systemctl daemon-reload && systemctl enable --now helmsman
systemctl status helmsman          # 验证 active
journalctl -u helmsman -f          # 实时日志
```

> 容器化模式下，显示栈（Xvfb/VNC）在**每个 run 容器内**自带，systemd unit
> **不需要** ExecStartPre 起宿主显示栈。

## 四、访问 + 发起任务

```bash
# 你的电脑：开 SSH 隧道
ssh -L 8080:127.0.0.1:8080 <server>

# 浏览器开 http://localhost:8080
#   - 填域名 + 需求 + 发起人（荣誉制标签）+ 模式（auto / explore / harvest）
#   - 发起 → 控制台 docker run 一个容器跑这个 mission
#   - 看实时：阶段进度、observation 流、日志、审计判决
#   - 点"连接"看实时浏览器（noVNC）→ 登录/验证码弹窗在这里人工操作
#   - 到 gate / 需要回答 / 审计存疑 → 页面弹出，浏览器通知提醒
```

## 五、多人 + 并发

- **多人共用一个控制台**：有 SSH 权限的人各开各的隧道，首页是共享看板（列出
  所有在跑的 run + 发起人）。**无账号系统**，荣誉制——谁都能看/停/回答任何 run。
  适合小团队互信，不适合对外。
- **每个 run 一个隔离容器**：独立浏览器、独立虚拟屏、独立 VNC 端口，互不串。
- **并发上限** `HELMSMAN_MAX_CONCURRENT_RUNS`（默认 6）；攒满后新任务排队。
- **别两个人同时跑同一域名**——World Model 和登录 profile 按域名共享，同域并发
  会互踩。不同站随便跑。

## 六、关键环境变量

| 变量 | 默认 | 说明 |
|------|------|------|
| `HELMSMAN_CONTAINERIZED` | `0` | `1`=每个 run 跑 `docker run`；`0`=跑宿主子进程（无隔离） |
| `HELMSMAN_PORT` | `8000` | 控制台端口 |
| `HELMSMAN_RUN_IMAGE` | `fsc-run:dev` | per-run 镜像名 |
| `HELMSMAN_MAX_CONCURRENT_RUNS` | `6` | 并发 run 上限 |
| `HELMSMAN_NOVNC_HOST_PORT` | `6080` | noVNC 宿主端口基址（每 run 分配各自端口） |
| `LLM_API_KEY/BASE_URL/MODEL` | — | 按名转发进容器，不进 argv |
| `DATABASE_URL` | — | localhost 会被自动改写成 host.docker.internal |

## 七、运维

```bash
# 更新代码（不改 src 只改 web/docs）
git pull && systemctl restart helmsman

# 改了 src/（agent 逻辑、prompt、工具）→ 必须重建镜像
docker build -f docker/run.Dockerfile -t fsc-run:dev . && systemctl restart helmsman

# 看在跑的 run 容器
docker ps --filter label=fsc-run

# 卡死的容器（控制台重启后会自动清理遗留的 fsc-run 容器，手动也行）
docker ps -a --filter label=fsc-run -q | xargs -r docker rm -f
```

**坑（实测）**：
- **磁盘**：镜像 ~4GB + 每个 run 的 artifacts 会涨；docker data-root 指数据盘
  （`/etc/docker/daemon.json` 的 `data-root`），别落系统盘。
- **共享机内存**：每个 headed Camoufox 容器吃 1-2GB，并发高 + 别人的进程容易
  OOM。无 swap 的机器加 swap 当安全垫，必要时调小并发。
- **Camoufox 二进制**：Dockerfile 里 `camoufox fetch` 从 GitHub 拉，国内机器慢/
  失败时重试，已内置 3 次重试 + tuna 镜像源。

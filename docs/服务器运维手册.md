# Helmsman 服务器运维手册

> 给操作员 / 维护者:怎么从任意一台电脑访问、使用、维护部署在服务器上的
> Full-Self-Crawl-Agent + Helmsman 网页控制台。
> 服务器:`118.196.19.109`(共享机器,只在 `/mnt/data1/full-self-crawl-agent-beta/` 下操作)。

---

## 0. 一句话现状

代码、依赖、PostgreSQL、Camoufox、显示栈(Xvfb+VNC)**都已部署在服务器**。Helmsman 网页
控制台从浏览器发起任务、看 recon/harvest 实时进度、内嵌可交互浏览器、应答登录/验证码 —
全部经**一条 SSH 隧道**。安全边界 = SSH(控制台只绑 `127.0.0.1`,公网访问不到)。

---

## 1. 从另一台电脑访问 —— 能,但需要 SSH 钥匙

**唯一入口是 SSH。** 任何能 SSH 进这台服务器的电脑都能用 + 维护;没有钥匙就进不来
(这是设计上的安全边界,不是 bug)。

新电脑要准备的东西:
1. **私钥** `Search-Data-Dev-Shanghai.pem`(从你现在这台机器 `~/.ssh/` 拷过去,妥善保管)。
2. **`~/.ssh/config`** 里加一段(把 IdentityFile 指向上面的私钥路径):
   ```
   Host 118.196.19.109
       Port 21022
       User root
       IdentityFile ~/.ssh/Search-Data-Dev-Shanghai.pem
   ```
   Windows 上 `~` 是 `C:\Users\<你>\.ssh\`。私钥权限要收紧(否则 ssh 拒用):
   - Linux/macOS:`chmod 600 ~/.ssh/Search-Data-Dev-Shanghai.pem`
   - Windows:右键属性→安全,只留当前用户可读。
3. 测试能连上:`ssh 118.196.19.109 "hostname"`。

> **任务在服务器后台跑,跟你的电脑无关。** 控制台在服务器的 tmux 里、mission 是独立子进程,
> 你笔记本关掉 / 断网 / 换电脑都不影响正在跑的任务。换台电脑重新建隧道、打开网页,继续看。

## 2. 日常使用(三步)

### ① 确保 Helmsman 在跑(在服务器上)
```
ssh 118.196.19.109
cd /mnt/data1/full-self-crawl-agent-beta
bash scripts/helmsman.sh status      # 看状态
bash scripts/helmsman.sh start       # 没在跑就拉起来(幂等,显示栈也会一起起)
```

### ② 建隧道(在你的电脑上,开一个终端**保持不关**)
```
ssh -L 9090:127.0.0.1:8080 118.196.19.109
```
- `9090` 是你本机端口,被占就换别的(如 9091);`8080` 是服务器上 Helmsman 的端口,别改。
- **这个终端就是隧道,关了网页就断。** 想后台常驻可加 `-fN`:
  `ssh -fN -L 9090:127.0.0.1:8080 118.196.19.109`(`-f` 转入后台,用 `ps`/`kill` 管理)。

### ③ 浏览器打开
```
http://localhost:9090/        ← 启动表单:填域名 + 需求 + 模式,点"发起任务"
http://localhost:9090/run     ← 发起后自动跳到这里:实时看板
```

**看板里能做的:**
- 阶段步骤条(RECON→GATE→HARVEST→DONE)、当前 session/step/URL、心跳新鲜度
- RECON 面板:locations / observations 实时流;HARVEST 面板:数据清单 + audit 判定
- **实时浏览器小屏**:点"连接"看 Camoufox 实时画面,点"⛶ 放大"全屏(ESC 退),可鼠标键盘交互
- **gate 横幅**:recon 跑完弹出,点"继续 harvest"或"停止"
- **需要你介入横幅**:撞到登录/验证码时弹出 → 在右侧实时浏览器里操作 → 点"完成"

> VNC 小屏默认不自动连(省流量),要**手动点"连接"**。万一黑屏:断开再连一次;或新标签直连
> `http://localhost:9090/vnc/vnc.html?autoconnect=true&resize=scale&path=vnc/websockify`。

## 3. 维护

### 起 / 停 / 重启 / 看日志(都在服务器上 `cd` 到项目目录后)
```
bash scripts/helmsman.sh start      # 起(含显示栈)
bash scripts/helmsman.sh stop       # 停 Helmsman(显示栈保留)
bash scripts/helmsman.sh restart    # 重启(改了前端代码后用)
bash scripts/helmsman.sh status     # 状态:端口/ tmux / 显示栈 / 当前 run
bash scripts/helmsman.sh logs       # 实时日志(Ctrl+C 退出查看)
```
> ⚠️ **重启会杀掉正在跑的 mission**(它是 Helmsman 的子进程)。要保住任务就别重启;改了前端
> 静态资源(CSS/JS)其实不必重启——已加 `?v=` 版本号缓存破坏,但改了 Python 后端必须重启。

### 更新代码(从 GitHub 拉最新)
```
cd /mnt/data1/full-self-crawl-agent-beta
git pull --ff-only                  # 墙内偶发 GnuTLS 中断,失败就重试几次
bash scripts/helmsman.sh restart    # 让后端改动生效
```
分支:`feat/helmsman-frontend`(前端在这个分支上;合并到 main 后改成 main)。

### 让 Helmsman 崩溃 / 重启后自动拉起(推荐,根治"进程死了没人管")
当前是 tmux 跑,进程崩了或服务器重启就没了(实际遇到过)。装 systemd 单元一劳永逸:
```
sudo cp scripts/helmsman.service /etc/systemd/system/helmsman.service
sudo systemctl daemon-reload
sudo systemctl enable --now helmsman
systemctl status helmsman           # 确认 active (running)
journalctl -u helmsman -f           # 实时日志
```
装了 systemd 后**别再用 `helmsman.sh start`**(会抢端口),二选一。停用:
`sudo systemctl disable --now helmsman`。

### 首次登录某站点(让 cookies 持久化)
站点需要登录时,在 VNC 小屏里手动登一次,cookies 存进
`artifacts/_profiles/{domain}/`,之后该域名的 run 自动带着登录态(跨 run 复用)。

## 4. 数据 / 产物在哪

```
artifacts/{domain}/runs/{run_id}/
├── samples/        # 主数据样本(primary data)
├── catalog/        # 索引/universe 清单
├── workspace/      # 脚本、调试、harvest 的 data/、human-assist 信号文件
├── transcripts/    # 每个 session 完整记录
├── verification/   # harvest audit 报告
├── strategy_report.md   # recon 结束的策略报告(gate 横幅展示这个)
├── requirement.txt      # 这次 run 的需求
└── status.json          # 实时心跳(phase/step/url/gate/assist)
```
- World Model 在 **PostgreSQL**(`recon_agent` 库,localhost:5432,postgres/postgres):
  locations / observations / sessions / models 四张表。
- **磁盘铁律**:系统盘 `/` 只剩 ~14G,所有大东西(artifacts、浏览器缓存)都已引到数据盘
  `/mnt/data1`,别往系统盘写大文件。

## 5. 排错速查

| 症状 | 原因 / 处理 |
|------|------------|
| 网页打不开 / 隧道报错 | 本机端口被占 → 换 `-L 9091:127.0.0.1:8080`;或 Helmsman 没跑 → 服务器上 `helmsman.sh start` |
| `bind: Address already in use`(建隧道时) | **本机**那个端口被占,不是服务器 → 换本机端口号 |
| 健康检查 8080 拒绝连接 | Helmsman 进程死了 → `helmsman.sh start`;想自愈就装 systemd(§3) |
| 端口 8000 别用 | 8000 被**另一个用户**的服务占着(`0.0.0.0:8000`),Helmsman 固定用 8080 |
| VNC 小屏黑屏 | 点"断开"再"连接";或显示栈没起 → `scripts/server_display.sh start`;或用 §2 的直连地址 |
| 发起任务 409 | 已有任务在跑(串行单任务设计)→ 先在看板点"停止",或等它结束 |
| SSH 频繁断 / git pull 失败 | 墙内网络抖动(GnuTLS)→ 重试即可 |
| Camoufox 下载失败 | GitHub releases 被限速 → 用 `https://gh-proxy.com/<github-url>` 镜像(见部署文档) |

## 6. 安全须知(别破坏)

- Helmsman **只绑 `127.0.0.1`**,公网访问不到,SSH 隧道是唯一鉴权边界。**绝不要**改成
  `0.0.0.0` 或把 8080 暴露公网 —— 那等于把一个无鉴权控制台 + 一个能操作已登录浏览器的
  VNC 直接挂到公网。
- noVNC(websockify)也只绑 `127.0.0.1:6080`,通过 Helmsman 的 `/vnc/` 同源反代访问,
  所以**只需一条隧道**,6080 不单独暴露。
- 私钥 `.pem` 是进入这台机器的钥匙,妥善保管,别提交进 git、别发群里。
- 这是**共享服务器**:只动 `/mnt/data1/full-self-crawl-agent-beta/`,别碰别人的数据 /
  别人的 tmux session(如 session `0` 是别人的)。

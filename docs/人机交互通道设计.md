# 人机交互通道设计：两个工具，一条通道

> 配套：`CLAUDE.md` §八（Human Assist 架构）、`docs/需求摄入与意图契约设计.md` §6、`docs/审计员设计.md`
> 日期：2026-06-09
> 全程用 kungal（采游戏真实剧本）举例。

## 一句话

人机交互只有**一条通道**：per-run、走 Helmsman 控制台、落共享盘信号文件、**应答能带文字**。两个工具是它的两种**言语行为**——`request_human_assist`（去操作 → 回 ack）、`ask_human`（用话回答 → 回文字）。intake 和 gate 不是 agent，**直接调通道**，不经过工具。

## 为什么是这个形状

旧通道只会「让人**操作**个东西 → 回一个 enum」：`request_human_assist` 回 `completed/cancelled/timeout`，gate 回 `continue/stop`。`HumanResponse.message` 字段一直躺着、注释写 `# future use`，**从没填过**——没有任何槽能把人的「话」传回来。

但新设计里要人介入的三处——intake 澄清、gate 校准、审计 UNCERTAIN 上报——**全是「人打字回答」**，payload 就是人那句话。而且桌面通道（Tkinter 弹窗 / 浏览器浮层）在容器里直接死、并发下也不寻址；**只有控制台 per-run 寻址、落共享盘、durable**，扛得住容器 + 并发。

所以：**保留通道的传输（status.json 标志 + uuid 信号文件 + supervisor 写回），把应答拓宽到能回文字。** 不加第四个对象。

## 两个工具

| | `request_human_assist`（保留，不动） | `ask_human`（新） |
|---|---|---|
| 言语行为 | 「去**操作**个东西」 | 「用**话**回答我」 |
| 入参 | `reason: str`（指令） | `question: str`（问题） |
| 人怎么应 | 在浏览器里操作，点完成/跳过 | 在控制台**文本框打字** |
| agent 拿回 | enum（done/skip）+「去 re-browse」 | **人的那句话** + status |
| 事后 | 要重新 `browse` 看页面变了没 | 直接读那句话，不用 re-browse |

`ask_human` 返回 `{status: answered|timeout|cancelled, answer: str|None, next_step_hint}`。`answer` 就是人打的字；超时/取消时 `answer=None`，`next_step_hint` 按调用语境指路（见「没人时怎么落地」）。

入参只有 `question` 一个自由文本字段——**不做「选项」模式**（守 `CLAUDE.md` §八「polymorphism 在人的回答里」）。真要约束选择，让 agent 在 question 里写「回 A 还是 B」，人照样打字。

## 一条通道：gateway 加 `ask()`

通道已经在了，只是从没接文字。接法是在 `HumanAssistGateway` 接口上加个**兄弟方法**——这就是「两个工具一条通道」落到接口上的样子：

```
HumanAssistGateway
  ├─ request(reason, page, timeout)  → HumanResponse(status)            # 旧，ack 回，要 page（拉浏览器前台）
  └─ ask(question, timeout)          → HumanResponse(status, message)   # 新，文字回（填那个一直空着的 message），不要 page
```

`WebGateway.ask` 完全镜像现成的 assist 路径（`WebGateway.request`），只换标志名：

- **抬给控制台**：`status_hook.set_flag(ask_pending=True, ask_question=..., ask_uuid=...)`，跟 `assist_pending/assist_reason/assist_uuid` 平行加进 `status.json` 的 `_state`。
- **控制台**：per-run dashboard 上渲染问题 + **一个文本框**（现在只有「完成/跳过」按钮，这是唯一要新建的 UI 件）→ 人打字提交。
- **写回**：supervisor 加 `answer_ask(uuid, text)`，写 `workspace/ask_response_{uuid}.json = {"status":"answered","answer":"..."}`。
- `WebGateway.ask` poll 到该文件、读 `answer`、返回 `HumanResponse(status="answered", message=answer)`。

本地 dev 的 Terminal/Tk/Overlay gateway 各给 `ask()` 一个朴素实现（终端 `input()` / Tk 文本 Entry），但**容器/服务器路径只走 WebGateway**。

> 标志位用平行的 `ask_*` 一套（最稳，照搬验证过的 assist 路径）。若日后嫌三套标志（gate/assist/ask）冗余，可收敛成一套带 `kind` + `expects: ack|text` 的通用请求——属重构，不是 MVP 必需。

## 三个入口

`ask_human` 是 **agent 循环里**的工具（要 `ctx`）。但 intake 和 gate **不是 agent**，像 `src/cli/gate.py` 现在那样**直接调 gateway.ask**：

| 入口 | 谁 | 怎么用通道 |
|---|---|---|
| **agent 跑中** | 执行 agent / 审计 agent | `ask_human` 工具 → `gateway.ask` |
| **intake** | 需求编译器（一次性 LLM，**还没 agent 循环**） | 直接 `gateway.ask` |
| **gate** | 阶段之间的 `gate.py` | 直接 `gateway.ask` + 决定 |

三个入口、**同一条文字通道**，都落 per-run 的信号文件。**并发不串**：每个 run 自带自己的通道，intake 也跑在自己容器里、是该 run 的第一步，外面零共享。

## intake 澄清：判断驱动，不卡轮数

把需求编译成意图内核时，若有**语义上的模糊**（kungal：「剧本」是真对白还是剧情梗概？），就 `gateway.ask` 问人，拿回答继续编译。

- **闸门是「现在还含不含糊」这个判断，不是固定问几次。** 需求一开始就清楚 → 0 问直接编译；真有模糊 → 该问几轮问几轮。轮次多是「确定性不够」的**症状**，不是要砍掉的东西。
- **天然限流**：人每轮都在环里答，runaway 被人的耐心throttle；人不答 → 超时。
- **没人答 → fail closed 硬停**（别拿猜的需求开跑，和「编译失败且无人 → 硬停」一致）。
- 这条**改掉**了之前「intake 最多一轮 ask（≤6 问）」的旧设定——闸门改成判断。

## gate：决定 + 可选意图校准文字

gate 现在 web 路径上只剩 `continue/stop`（`gate.py:86`「`edit` is not offered by the web console」），校准能力=0；`edit` 的旧实现是宿主机 `subprocess.run($EDITOR, requirement.txt)`，容器里没有。

改：`gate_response.json` 从 `{decision}` 扩成 `{decision, requirement_edit?}`。operator 在控制台文本框改/补意图，`requirement_edit` 跟着回来，mission 据此**重新钉意图**（「人版本化」出新版本，旧版归档）。**干掉 `$EDITOR` hack**，gate 校准终于在 web 路径上活了。

## 交互界面：就在每个 run 自己那一页

每个 run 已经有自己的 dashboard 页（`/run/{run_id}`），里面通过 `/vnc/{run_id}/` 嵌着该 run 的浏览器（noVNC）。**问题 + 文本框就摆这同一页**，紧挨着浏览器视图——操作某个 run 的人本来就盯着这页。

- assist（完成/跳过按钮）已经渲染在这页；ask 的文本框、gate 的「决定 + 校准框」加在同一处。
- **并发下「谁在等你」**：run-list 从现成的 `ask_pending / gate_pending / assist_pending` 标志显示「等你输入」状态（一个红点/badge），人扫一眼列表知道开哪个 run。**不另起全局聚合器**——状态本来就在 status.json 里，挂 run-list 即可。

## 没人时怎么落地

| 调用语境 | 超时/无人 → |
|---|---|
| `request_human_assist`（agent 卡住） | 已有：steer 去自主路径 / `mark_done(blocked)`（不变） |
| **intake 澄清** | **fail closed 硬停**（别拿猜的需求开跑） |
| **gate** | 已定：干净自动续 / 存疑 hold |
| **审计 UNCERTAIN 上报** | **卡住等人**（hold，不自动续、不带 flag 偷跑）——和 gate 存疑同形 |

> **UNCERTAIN 一律 hold**：审计拿不准就停在那等人，哪怕无人值守也宁可停（这正是「绝不默认 PASS」的延伸）。代价：无人时 run 会卡住不动，这是**故意的**——拿不准的产物不许偷偷算过。

## 不做什么

- 不做选项/表单模式，只自由文本（§八）。
- intake **不做多轮自由 chat**——是「判断驱动的澄清循环」，每轮服务于「消除一个具体模糊」，不是开放聊天。
- 不另起全局「待办聚合器」，先挂 run-list 的现成状态。
- 不碰跨 session 并发 assist（`CLAUDE.md` §八维持）。
- 桌面 gateway（Tk/Overlay）保留作本地 dev，**不为容器/并发投入**。
